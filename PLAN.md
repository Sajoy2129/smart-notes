# Smart Notes – PostgreSQL Support Plan

> This file becomes the new `PLAN.md`.

## Context
Smart Notes stores everything in one SQLite file (`smart_notes.db`). I want it to also run on
**PostgreSQL** (a database server; for example AWS RDS or Neon), chosen by one environment variable:

- `DATABASE_URL` set, e.g. `postgresql://user:pass@host:5432/smart_notes` → use PostgreSQL.
- `DATABASE_URL` not set → use SQLite exactly as today (`DATABASE_PATH`, or `smart_notes.db`).

The live server keeps using SQLite until I choose to set `DATABASE_URL`. Nothing changes for it
by default.

## Approach: one `db.py` that speaks both
All differences stay inside `db.py`. `app.py` keeps passing one string around:
`app.config["DATABASE"]` holds either a file path or a `postgresql://` URL. `db.py` looks at it
to pick the driver. Function names and arguments stay the same, so routes and most tests don't change.

**Driver:** `psycopg` version 3 (`pip install "psycopg[binary]"`), the standard PostgreSQL
library for Python. `[binary]` brings its own compiled parts, so no extra system install.

### SQLite vs PostgreSQL differences and how each is handled
| Difference | SQLite | PostgreSQL | Plan |
|---|---|---|---|
| Placeholders | `?` | `%s` | Keep writing `?`. One helper swaps to `%s` for Postgres (our SQL never has a literal `?`) |
| Auto ids | `INTEGER PRIMARY KEY AUTOINCREMENT` | `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | `SCHEMA` gets an `{id_column}` slot filled per database |
| New row's id | `cursor.lastrowid` | not available | Use `INSERT ... RETURNING id` on both (SQLite ≥ 3.35; I have 3.50) |
| Dict-like rows | `sqlite3.Row` | `psycopg.rows.dict_row` | Set inside `_connect()` |
| Many statements | `executescript` | not available | Split `SCHEMA` on `;` and run each one |
| Case-blind sort | `COLLATE NOCASE` | not available | `ORDER BY LOWER(projects.name)` works on both |
| Upsert `jobs + 1` | unqualified ok | can be ambiguous | Write `ai_usage.jobs` (valid in both) |
| Read columns | `PRAGMA table_info` | not available | Upgrade step is SQLite-only: Postgres tables are always new, created with every column |
| `with conn:` | commits, doesn't close | commits **and** closes | One `_connect()` context manager: commit on success, rollback on error, always close |

Dates stay `TEXT` in ISO format on both, so `nice_date`, `timeago` and sorting keep working.

### New helpers in `db.py` (small, each with a docstring)
- `is_postgres(database)`: True if the string starts with `postgresql://` or `postgres://`.
- `_connect(database)`: a `@contextmanager` that opens the right connection (dict rows),
  yields it, commits/rolls back and always closes. It replaces `with closing(_connect(...)) as conn, conn:`.
- `_execute(conn, sql, params=())`: swaps `?`→`%s` when the connection is Postgres, runs the SQL, returns the cursor.

## Steps (each ends with green tests and one small commit)

**Step 0: Housekeeping.** `git mv PLAN.md PLAN-deploy.md`, add this plan as `PLAN.md`.
Commit: "Start the PostgreSQL plan; keep the deploy plan as PLAN-deploy.md".

**Step 1: Refactor `db.py` without changing behaviour (SQLite only).** Add `_connect()` as a
context manager and `_execute()`. Switch inserts to `RETURNING id`, `COLLATE NOCASE` to `LOWER()`,
qualify `ai_usage.jobs`, run `SCHEMA` statement by statement. Run `pytest`: all existing tests must
still pass. This proves the refactor broke nothing *before* Postgres is involved.
Commit: "Prepare db.py for a second database: one connect helper, RETURNING ids".

**Step 2: Add PostgreSQL to `db.py`.** Add `psycopg[binary]` to `requirements.txt` (pinned, via
`pip install` then `pip freeze`). Fill in the Postgres branch of `_connect()`, `{id_column}`, and skip
`_add_missing_columns` on Postgres. The SQLite tests still pass.
Commit: "Let db.py use PostgreSQL when given a postgresql:// URL".

**Step 3: Choose the database from `DATABASE_URL` in `app.py`.** Change line 71 to:
`db_path or os.getenv("DATABASE_URL") or os.getenv("DATABASE_PATH", db.DEFAULT_DB_PATH)`.
Add `DATABASE_URL` to `APP_ENV_VARS` in `conftest.py`. New tests in `test_settings.py`:
- `DATABASE_URL` set → `app.config["DATABASE"]` is the URL (mock `db.init_db`, no real server needed)
- `DATABASE_URL` and `DATABASE_PATH` both set → the URL wins
- neither set → still SQLite (the existing test covers `DATABASE_PATH`)

Never print the URL in errors or logs, because it contains the password.
Commit: "Use PostgreSQL when DATABASE_URL is set, SQLite otherwise".

**Step 4: Run the whole test suite against a real PostgreSQL.** In `conftest.py`, if
`TEST_DATABASE_URL` is set, the `db_path` fixture drops and re-creates the tables in that database
for each test instead of making a temp `.db` file. Without `TEST_DATABASE_URL`, tests run on SQLite
as today, so no Postgres is needed day to day.
*Done differently:* no skip markers were needed. The SQLite-only tests (upgrade, backup,
`DATABASE_PATH`) make their own temp `.db` files, so they keep testing SQLite in both runs.
Added: a safety check refusing any database without "test" in its name (tests drop every table),
and a pytest header line naming the database used.
Commit: "Run the tests on PostgreSQL too when TEST_DATABASE_URL is set".

**Step 5: Docs.** Short "Using PostgreSQL" section in `DEPLOYMENT.md`: what `DATABASE_URL`
looks like, that `backup.sh` only covers SQLite (Postgres needs `pg_dump`), and that the live
server is unchanged until `DATABASE_URL` is added to its `.env`.
Commit: "Document the DATABASE_URL setting".

## Out of scope (possible later steps)
- Copying existing notes from the live SQLite file into PostgreSQL (a one-off migration script).
- Switching the live server to Postgres and a `pg_dump` backup script.
- Connection pooling (reusing connections). This is a small single-user app, so one connection per request is fine.
